# ohm-website-patches

OHM customizations for [openstreetmap-website](https://github.com/openstreetmap/openstreetmap-website), kept separate from the fork history. Generated by diffing `ohm-website:staging` against its upstream merge-base (see `UPSTREAM_BASE`).

Translations (`config/locales/*`) are excluded — Translatewiki manages them. Lockfiles (`Gemfile.lock`, `yarn.lock`, `db/structure.sql`) are excluded — regenerate them from the patched `Gemfile`/`package.json`.

## Layout

- `patches/` — one `.patch` per upstream file OHM modifies, mirroring the repo tree. Most are small (2–10 lines). Applied with `git apply --3way`, so they tolerate upstream drift and fail loudly on real conflicts.
- `overlays/` — whole files OHM adds (timeslider, logos, sprites, `lib/date_range.rb`, ...) plus modified binaries (PNGs). Copied over the checkout; these paths have no upstream counterpart, so no conflict risk.
- `REMOVALS` — upstream files OHM deletes.
- `UPSTREAM_BASE` — upstream commit the patches were generated against.

## Usage

```bash
./scripts/apply.sh /path/to/checkout
```

Or set `OHM_WEBSITE_DIR` and call without args. Order: patches, then overlays, then removals.

## Regenerating

From an `ohm-website` checkout with the `upstream` remote fetched:

```bash
MB=$(git merge-base staging upstream/master)
git diff --name-status "$MB" staging   # A -> overlays/, M -> patches/, D -> REMOVALS
```

Text `M` files: `git diff "$MB" staging -- "$f" > patches/$f.patch`. `A` files and binary `M` files: `git show "staging:$f" > overlays/$f`. Update `UPSTREAM_BASE` with `git rev-parse "$MB"`.
